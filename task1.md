### Сравнение векторных баз ChromaDB и FAISS:

| Критерий                | **ChromaDB**                                                                                      | **FAISS**                                                                                                                  |
| ----------------------- | ------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| **Скорость поиска**     | Хорошая для средних объёмов (до 1–10 млн векторов). Поддержка HNSW. Зависит от бэкенда.           | Лучшая в индустрии. Оптимизирована под миллиарды векторов. Поддержка GPU, HNSW, IVF, квантизации. Минимальная латентность. |
| **Скорость индексации** | Медленнее FAISS из-за накладных расходов (метаданные, логи). Автоиндексация при вставке.          | Очень быстрая. Требует ручного управления: построение → обучение -> добавление -> сохранение.                              |
| **Сложность внедрения** | Низкая. Установка одной командой. Встроенный API, HTTP-сервер (опционально), метаданные, фильтры. | Высокая. Только библиотека. Нет метаданных/фильтров "из коробки". Требует глубокого понимания индексов.                    |
| **Сложность поддержки** | Средняя. Автоматическое управление индексами. Возможны сложности при масштабировании.             | Высокая. Ручное управление индексами, сериализацией, обновлениями. Нет транзакций или репликации.                          |
| **Удобство в работе**   | Очень высокое. Единый API, коллекции, метаданные, интеграции (LangChain, LlamaIndex).             | Низкое для новичков. Только низкоуровневый API. Метаданные — через внешние БД.                                             |
| **Стоимость владения**  | Низкая на старте. Бесплатна. При масштабе — требует сервера. Потребляет больше RAM.               | Низкая в production. Бесплатна. Эффективное использование CPU/GPU и памяти. Минимальные накладные расходы.                 |

> **FAISS** если: Нужна максимальная производительность поиска, работаете с очень большими наборами данных (миллиарды векторов), нужно GPU-ускорение и если есть технические ресурсы для интеграции и поддержки

> **ChromaDB** если: Нужно быстрое внедрение векторного поиска, простота использования и разработки, встроенная поддержка метаданных и фильтрации, зотим готовое решение с API и клиент-серверной архитектурой, работаете с данными среднего объема (до сотен миллионов векторов)

### Конфигурация сервера

По заданию:
Объём данных: ~21 250 документов (Markdown, Confluence, PDF) -> **~15–25 млн токенов после препроцессинга.**
Рост: ~400 страниц/мес → ~300K токенов/мес -> **требует периодической переиндексации.**
Пользователи: ~50–150 активных пользователей (разработчики, саппорт, менеджеры, новички).
Задачи: семантический поиск, RAG, фильтрация по метаданным (тип документа, проект, роль), **мультиязычность** (английский + скандинавские языки).
Конфиденциальность: корпоративные данные -> **локальное развёртывание обязательно.**
SLA: ожидается низкая латентность (<1–2 сек на ответ), высокая релевантность.
